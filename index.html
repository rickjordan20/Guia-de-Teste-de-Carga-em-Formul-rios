🚀 GUIA PRÁTICO

Teste de carga em formulários com Grafana k6

Aprenda, passo a passo, a descobrir como um formulário se comunica com o servidor, planejar a carga e gerar o script k6 que será executado no Grafana.

🔎 Network 👥 VUs 🧩 Payload ⚙️ Script k6
1
ESCOLHA SEU TESTE

Qual formulário você vai testar?

Escolha a funcionalidade. O guia abaixo será atualizado automaticamente com as orientações específicas para ela.

2
ANTES DE COMEÇAR

Entenda o que estamos fazendo

✅ Teste funcional

⚡ Teste de carga

Observa como a mesma operação se comporta quando vários usuários virtuais a executam.

Nosso objetivo aqui é montar corretamente o teste. Os resultados, evidências e a análise final serão registrados na atividade da QA Academy.
3
DEVTOOLS

Descubra a requisição do formulário

Aplicação → F12 → Network → Fetch/XHR
  1. Abra a página correta.

  2. Pressione F12 e abra Network.

    Se quiser reduzir a quantidade de itens exibidos, selecione Fetch/XHR.

  3. Execute a operação manualmente.

  4. Encontre a requisição responsável pela operação.

    Não escolha uma requisição apenas pelo nome. Clique nela e confira as informações.

💡 Você chegou ao lugar certo se: ao clicar na requisição, conseguir visualizar as abas Headers e Payload.
4
HEADERS

Descubra Método, URL e Status

Na requisição selecionada, abra Headers e procure:

1 Request Method

Qual método HTTP foi utilizado?

2 Request URL

Para qual endereço a operação foi enviada?

3 Status Code

Qual resposta o servidor devolveu?

🧠 O que significam os métodos HTTP?

GET buscar/consultar

POST enviar/criar

PUT atualizar/substituir

PATCH atualizar parcialmente

DELETE excluir

5
FRONTEND × BACKEND

Por que a Request URL pode ser diferente da página?

🌐 FRONTEND Página, campos e botões
envia a requisição →
⚙️ BACKEND Processa a operação

No TechEduca, a página pode estar publicada no GitHub Pages, enquanto algumas operações podem ser processadas por um backend hospedado em outro serviço.

⚠️ Não tente adivinhar o endereço do backend. Em cada sistema ele pode estar em um lugar diferente. Para este teste, utilize a Request URL encontrada no Network .
6
PAYLOAD

Descubra quais dados são enviados

Na mesma requisição, abra Payload. Observe os nomes dos campos e os valores enviados. Você utilizará essas informações como referência para montar o Payload do seu teste.

🔐 Segurança: utilize somente dados fictícios ou contas de teste autorizadas. Não coloque senhas pessoais, CPF, dados bancários ou informações confidenciais no script.
7
GERADOR DIDÁTICO

Preencha o que você descobriu

Agora transforme sua investigação em uma configuração de teste. Não preencha por adivinhação: use o que você encontrou no Network.

Monte o Payload do seu teste

Use como referência os campos que você encontrou anteriormente em Network → Payload.

💡 Agora é com você: informe o nome de cada campo e o valor que deseja utilizar no teste. Você pode modificar os valores para utilizar dados fictícios, mas os nomes dos campos precisam corresponder ao que a aplicação espera .

👥 Planeje a carga

Defina quantos usuários virtuais serão simulados e quantas vezes cada usuário executará a operação.

? VU(s) × ? execução(ões) = ? requisições esperadas
💡 Por que isso é importante? Neste guia usaremos per-vu-iterations . Assim, você consegue saber antecipadamente quantas execuções serão realizadas: VUs × execuções por VU .

10
GRAFANA CLOUD

Leve o script para o k6

Create a test → Manual → Web application → Write a script
  1. Abra o editor de script.

    O Grafana pode mostrar inicialmente um exemplo da aplicação QuickPizza.

  2. Apague o código de exemplo.

    QuickPizza é apenas uma demonstração do Grafana e não representa o seu formulário.

  3. Cole o script gerado neste guia.

    Antes de executar, confira novamente URL, VUs, execuções e status esperado.

  4. Comece pequeno.

    Faça primeiro um teste de controle com 1 VU × 1 execução = 1 requisição . Se funcionar, avance para a carga solicitada pelo instrutor.

⚠️ Não aumente a carga sem autorização. Testes de carga geram tráfego real. Use somente sistemas e cargas autorizados para a atividade.
🎯

Pronto para executar.

Depois da execução, registre os resultados, evidências e sua análise diretamente na missão correspondente da QA Academy .
